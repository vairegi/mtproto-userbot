WHAT CHANGED

1. miniapp/backend/app/services/scraper_bridge.py
   Chip/sort Turso reads now use allow_stale=True by default. The cache
   rows are never deleted (cache-never-expires design), but reads were
   gated on TTL freshness — aged rows read as MISSes, the upstream
   nhentai fallback was 429-backoffd, has_more flipped False, and the
   Mini App next button grayed out after page 2. Serving stale rows
   keeps pagination alive; ScraperBot refreshes rows on schedule anyway.
   Env toggle: USE_OLD_CACHE=0 restores the old strict-fresh behavior.

2. miniapp/backend/app/routes/trending.py
   New endpoint GET /api/trending/scraper-tags?limit=10 — returns the
   trending tag list ScraperBot (BOT 1) scrapes every 24h from nhentai
   popular-today (Mongo scraper1_state, _id="trending_tags"). Fail-open:
   items=[] on any error.

3. miniapp/frontend/js/pages/search.js
   The "Try:" hint row below the search bar now reads
   "Try Searching These:" followed by tappable tag:<slug> chips fed by
   the new endpoint. Tapping one fills the search box and searches.
   If the endpoint returns nothing, the original static hints show.
   Import of home-rows.js bumped to ?v=1.22.5 (importmap trailing-slash
   mappings cannot carry versions — every changed file must bump at its
   import sites; detail-sheet.js and registry.js needed no bumps since
   they are unchanged / unversioned).
