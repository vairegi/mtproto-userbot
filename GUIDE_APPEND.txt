WHAT & WHY
----------
Turso's 500M-reads/month cap nearly locked the account twice. Mongo Atlas
has no per-read billing, so this makes Mongo-2 the read primary while
Turso keeps every write (warm fallback + your existing 12h backup stays
valid). BOTH phases are in this one zip — you control go-live purely by
env vars, no redeploy needed between phases.

ARCHITECTURE
------------
WRITE (all 3 bots, every write):
  payload -> normalize (unchanged) -> Turso write (unchanged, first)
          -> Mongo-2 upsert (second) -> ONE visible log line:
             "DUAL-WRITE key=gallery:123 turso=OK mongo2=OK (58ms)"
  A Mongo-2 failure NEVER blocks — logs mongo2=FAIL, Turso copy intact.

READ (all 3 bots):
  Mongo-2 find_one -> HIT  = zero Turso reads (log: "MONGO2 HIT key=...")
                   -> MISS = Turso fallback (log: "MONGO2 MISS ...")
  The v1.28 backup + dual-writes keep Mongo-2 current; misses self-heal.

TTL parity: Mongo TTL index on expires_at (partial: >0 only), so expiring
rows auto-delete in Mongo exactly like Turso; expires_at=0 never-expire
rows persist in both.

/SIMILAR: re-enabled by default, scored on Mongo-2 (miniapp/backend/app/
services/similar_mongo.py) — the full-corpus scan that cost ~15k Turso
rows/request is now free. Route falls back to the old Turso engine if
Mongo-2 returns nothing for a gallery.

-------------------------------------------------------------------------
