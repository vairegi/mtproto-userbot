## v12.40k — Bot2Fetcher Bot API log dashboard (2026-08-23)

### Change
The log-channel dashboard no longer piggybacks on the userbot session.
It now speaks Telegram's Bot API directly (httpx to
`api.telegram.org/bot<token>/…`) via a dedicated bot account:

  * new env var: BOT_2_PDF_FECTHER (aliases also accepted:
    LOG_BOT_TOKEN, DASHBOARD_BOT_TOKEN, TELEGRAM_LOG_BOT_TOKEN)
  * one merged message per boot, edited in place every 30 s
  * Markdown v1 parse mode with special-char escaping
  * message id persisted in Turso bot2_fetch_state['_dashboard'].bot_msg_id

Why: v12.40i / v12.40j tried to post through slot 1's Telethon session,
which required the userbot to have iter_dialogs cached the log channel
peer. On freshly-added bots that resolve step is fragile. A Bot API bot
is HTTP-only, no per-session peer table, works instantly once admin.

### Setup
1. @BotFather -> /newbot -> get token.
2. Add the new bot to the log channel as ADMIN (post-messages + edit
   permissions).
3. Render env: BOT_2_PDF_FECTHER=<token>, LOG_CHANNEL_ID=<-100…>.
4. Deploy. Log should show
   `📊 log bot ready: @yourbot (id=…)`
   and the dashboard message appears within 30s.

### Boot log added
    📊 log bot ready: @yourbot (id=…)         ← Bot API path
    📊 dashboard started via Bot API (msg id: …)
On misconfig:
    📊 dashboard disabled — BOT_2_PDF_FECTHER … not set / rejected …

### Rollout
Copy `Bot2Fetcher/` over, push, Manual Deploy. Add BOT_2_PDF_FECTHER
env var.
