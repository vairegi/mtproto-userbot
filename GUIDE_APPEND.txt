GUIDE_APPEND — v12.71 (2026-09-05) — Reader skip-fix
WHAT: Read worked but images loaded with holes (pages 1-4 blank, 5-7
loaded, 8-10 blank...). Cause: reader.js trimWindow() dropped a trimmed
page's <img> and left an EMPTY placeholder; scrolling back up never
re-mounted it (bottom-only sentinel + advanced nextIdx), so trimmed
pages stayed blank forever. Now: mountPage() is idempotent + keyed by
page number (mountedByN); placeholders keep their data-page stamp and
are REUSED in place on re-mount; new ensureVisibleWindow() on every
scroll tick mounts any unmounted page within ±5 of the viewport;
trimWindow() drops pages by DISTANCE from the viewport; progress counter
tracks the visible page; img.onerror leaves a "tap to retry" placeholder
instead of an invisible gap. RAM cap unchanged (MAX_MOUNTED=21).
Server cost: ZERO image bandwidth on Render (pages hotlink
i1-i4.nhentai.net — verified 200 image/webp on all four hosts). Mongo
stores only pages_meta JSON (~1.5 KB/gallery), never images.
FILES: miniapp/frontend/js/plugins/reader.js, GUIDE.md, GUIDE_APPEND.txt.
(No backend change.)
DEPLOY: drop on repo root, commit, push, redeploy Bot 0 only; users must
fully close + reopen the Mini App once to pick up the new reader.js.
VERIFY: open any gallery with 10+ pages, scroll to bottom, scroll back
up — every page re-loads in place, progress tracks the visible page, no
blank holes. CI green.
