WHAT CHANGED
1) ScraperBot (Bot 1): new env var BOT1_PUBLIC_BASE_URL. main.py now runs a
   "webhook keeper" task at startup: it checks getWebhookInfo and, if the URL
   does not point at <BOT1_PUBLIC_BASE_URL>/telegram, registers it with
   ?s=<BOT1_WEBHOOK_SECRET> automatically, then re-verifies every 6 hours.
   You never run setWebhook manually again — after a token change or a Render
   account move, just update BOT1_PUBLIC_BASE_URL (+ BOT1_TOKEN) and deploy.

2) Bot2Fetcher (Bot 2): dashboard message is now wrapped in a Markdown v1
   code fence (the quoted look Bot 1 uses) and retries as plain text if a
   send/edit still fails. The repeating
   400 "cant parse entities ... byte offset 204" spam is gone.

DEPLOY STEPS
1. Drop files onto repo (paths correct), commit, push.
2. On BOTH Render services nothing changes except Bot 1: add env var
      BOT1_PUBLIC_BASE_URL = https://scraperbackup.onrender.com
3. Bot 1 redeploys; watch the log for "webhook keeper armed" and
   "🔗 webhook auto-registered".
4. Send /health to ScraperBot — should answer (allow 30-60s cold start).
5. Bot 2 redeploys; the log channel dashboard reappears as a quoted block
   and the 400 spam stops.
