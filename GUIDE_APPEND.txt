WHAT CHANGED & WHY
------------------
Turso free tier = 500M ROWS READ / month (rows touched, NOT rows returned).
Usage was 292.45M on Sep 4 — pace ~2.2B/month, i.e. a lock-out around Sep 10.
Live census (read-only, via /v2/pipeline):
  nhentai_cache 18,930 rows: 15,048 gallery:* + 3,857 search:* + 25 similar:*
  2,136 of the search rows are LEGACY `search:search:*` (55%) — probed on
  every typed search but never matched (they hold raw dict envelopes while
  the read path now expects canonical lists).

Fixes (all backend; no frontend / no cache-contract change):
  1. hf_scraper.py — _turso_key_for: typed-search keys map DIRECTLY to the
     canonical row `search:q=<q>|sort=date|page=<N>`. The legacy
     `search:search:*` row is never read or written again. (-50% typed-
     search reads)
  2. hf_scraper.py — search() warm probe reads ONLY the sort=date variant
     (was date+popular: 2 reads/page -> 1), and accepts canonical LIST
     payloads. This silences the recurring "'list' object has no attribute
     'get'" WARNING from the Render log AND lets Bot 1's warm rows finally
     serve Bot 0 typed searches (title via title_en_clean, thumb via cover
     string, English filter skipped for card lists — Bot 1 pre-filters).
  3. hf_scraper.py — L2 cache writes restricted to canonical keys
     (gallery:* / search:q=*) so legacy shapes can never re-appear.
  4. Bot2Fetcher/app/turso_store.py — list_gallery_ids got a 10s memo
     (env BOT2_LIST_MEMO_TTL_SEC): back-to-back producer ticks share ONE
     scan. Plus ensure_schema now CREATEs INDEX idx_nhentai_cache_cached_at
     — before this, the "incremental watermark" scan still touched all
     ~15k gallery rows every cycle because cached_at was unindexed.
     (NOTE: the token-bucket consume path was audited and deliberately NOT
     memoized — it is one atomic single-row UPDATE, already minimal.)
  5. scripts/purge_legacy_search_keys.py — NEW. Resumable batched purge of
     the 2,136 legacy rows (cursor = remaining keys, so re-running after a
     crash just continues). Dry-run mode included. Run ONCE by hand (below).
  Also cumulative: hf_scraper.py carries the v12.54 backoff softening
  (NH_RATE_LIMIT_TTL_SEC 20 / CAP 120) in case the v12.54 zip was not yet
  applied to the repo. Apply the v12.54 zip FIRST, then this one — the two
  are compatible either way for hf_scraper.py (same content).

EXPECTED EFFECT
---------------
  * Typed searches: 2 Turso reads/page -> 1 (and that 1 now actually HITs
    Bot 1's warm rows instead of falling through to upstream).
  * Bot 2 producer: full/delta scans collapse from "every tick touches
    ~15k rows" to "one scan per 10s window, and delta scans touch only new
    rows once the index exists". This was likely the single biggest read
    consumer (15k rows x every few seconds, 24/7).
  * Net projection: well under 500M reads/month. Watch the Turso dashboard
    over the next 24-48h.
