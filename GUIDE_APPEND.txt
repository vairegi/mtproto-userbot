## v12.40e — Bot2Fetcher spoiler cover + Bot-0 caption format (2026-08-23)

### Symptom (v12.40d, screenshot from operator)
1. Coverpost landed in the DB channel as an "unnamed 29 KB application/*"
   FILE, not an image.
2. No spoiler blur on the cover.
3. Caption was the old custom format (📖 title / 🆔 / 🔗 URL / 📄 pages)
   instead of Bot 0's house format.
4. PDF not forwarded in some jobs.

### Root cause
`_post_cover` passed raw CDN bytes + a filename to `send_file`, which
Telegram treated as a document upload. Webp/gif covers made it worse
(v11.2 lesson: InputMediaUploadedPhoto rejects non-JPEG). Caption builder
was my own format, not cover_poster._format_caption.

### Fix — replicates repo-root cover_poster.py v12.34l exactly
- New `app/cover_normalise.py`: Pillow convert to RGB JPEG before upload
  (same job as cover_image_normalise.py).
- `_post_cover`: download with browser UA + nhentai Referer → normalise
  → `client.upload_file` → `InputMediaUploadedPhoto(spoiler=True)` →
  `send_file(force_document=False)`. Fallbacks: plain photo → text-only
  caption. Photo + spoiler every time bytes are available.
- `meta.caption_for` rewritten byte-compatible with
  cover_poster._format_caption: bold clean title (event prefix + trailing
  brackets stripped), '➤ #<gid>', aligned meta rows Groups → Parodies →
  Artists → Characters → Languages → Categories, trailing '➤ Tags:' row,
  NO nhentai URL, NO pages line. Tags stay typed ({name,type}) from the
  Turso payload so grouping matches Bot 0.
- PDF: forward with drop_author=True; fallback download + re-upload as
  document with clean bold title caption. requirements.txt gains pillow.

### Rollout
Copy `Bot2Fetcher/` over the existing folder, push, Manual Deploy.
Env unchanged.
