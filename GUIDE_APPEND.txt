GUIDE_APPEND — v12.90 (2026-09-09) — bandwidth diet (adaptive backoff + slim fetches + activity card)
WHAT: Bot 1's outbound bandwidth kept climbing after v12.89 because the
write-destination fix didn't touch the real hogs: the details sweeper's
nonstop Mongo-1 freshness reads (~25 full docs/tick/min ≈ 75–150 MB/hr
idle), the verbose ?include=related,suggestions,comments on every cold
gallery fetch (dead weight — Bot 0 lazy-fetches suggestions itself, Bot 2
never reads them), and the log-channel status card editing every ~15s. Now:
(1) the sweeper backs off exponentially to a 5-min cap when the cache is
fully warm and snaps back to the 60s base tick on any activity; (2) gallery
fetches are slim by default (DETAILS_SLIM_FETCH=0 restores the verbose
include); (3) the freshness check projects ONLY expires_at (~80 B/row —
document existence proves payload presence since Bot 1 has no tombstone
path); (4) the status card edits only when its data fingerprint changes
(≥30s apart) plus a 5-min idle refresh. Zero data-contract changes.
