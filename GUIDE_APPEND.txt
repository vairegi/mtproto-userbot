## v12.41 — Bot2Fetcher: loud dashboard logging + per-slot InputPeer Mongo cache

Ship date: 2026-08-25
Files: app/dashboard.py, app/mongo_state.py, app/fetcher.py, main.py, app/turso_store.py, common/turso_http/*

1) dashboard.py — port of ScraperBot v1.21 loud-logging. LogBot._call now logs
   `bot api <method> failed [<error_code>]: <description>` (400-char cap) so a
   400 storm is diagnosable from Render logs with one grep. Added
   _coerce_chat_id so a numeric-string LOG_CHANNEL_ID is sent as int
   (prevents silent "chat not found"). "message is not modified" whitelisted.

2) mongo_state.py — new PeerCache class (collection `bot2_peer_cache`).
   Persists each slot's resolved Telethon InputPeer, keyed by
   (slot_idx, kind, session_fingerprint). session_fingerprint = sha256 of the
   slot's StringSession — rotating a session auto-invalidates the row (this is
   what prevents regressing to the v12.40i cross-session PeerIdInvalidError).

3) fetcher.py — _warm_and_resolve() now consults PeerCache first. On a warm
   restart (same session) the entity loads in ONE Mongo read and the 200-dialog
   iter_dialogs scan is SKIPPED. On any miss/mismatch/error it falls back to
   the live resolution path, then writes the fresh entity back to the cache.
   Cache is an optimization, never a hard dependency.

4) main.py — wires fetcher.peer_cache = PeerCache(_db).

5) turso_store.py — _pipeline delegates to the NEW shared package
   common/turso_http (see Overall #1). Falls back to the pre-v12.41 inline
   path if the shared package isn't importable, so deploy is safe either way.

Rollback: git checkout HEAD -- Bot2Fetcher. New Mongo collection
`bot2_peer_cache` is harmless to leave behind.
