## v12.44 — Bot2Fetcher: bulletproof cache-field coercion + skip elimination

Ship date: 2026-08-26
Files: app/meta.py, app/fetcher.py, app/mongo_state.py, app/turso_store.py
(superset — includes v12.42 no-images skip and v12.43 cover construct)

1) PERMANENT crash fix (meta.py)
   Root cause: the same gallery:<id> Turso row can be written by THREE
   different code paths (BOT 0 nhentai_cache.put, BOT 1 normalize_gallery,
   BOT 1 search-card passthrough) plus legacy versions — so `pages` has
   arrived as int, str, list AND dict. Each new shape crashed the reader.
   Fix: new _coerce_int() accepts int/float/str/list/tuple/dict (nested
   pages/num_pages/value/count/n keys), returns 0 only when nothing is
   recoverable. `title` is also coerced from dict to string (legacy raw-v2
   rows). The reader can no longer crash on ANY field shape, no matter
   which writer produced the row. Smoke-tested against every shape from
   the crash chain.

2) Skip elimination (fetcher.py + mongo_state.py)
   Problem Ryan measured: 146 PDFs in 15h — slots were spending most of
   their time re-claiming galleries already in the DB channel.
   Fix: Fetcher keeps process-lifetime sets _known_done / _known_failed.
   _build_queue_order() drops these gids BEFORE the queue, so slots never
   touch known-finished work. Sets are fed by: claim()=="done"/"failed",
   successful completion, v12.42 permanent skip, no-meta drop, and the
   @Gallery_DLBot timeout drop (previously both re-queued forever).
   New Galleries.get_known_states(gids) gives a ONE-round-trip batch
   status lookup (wired for future use / restarts).
   mark_completed() and mark_failed() now $unset the v12.42 retry counter
   so finished rows are permanently clean.

3) Root-cause fix: dead recent filter (turso_store.py)
   list_recent_search_ids() filtered on key LIKE '%recent%' — which
   matched ZERO rows because Recent is written as 'search:date:page<N>'
   (nhentai's sort param is "date"). Recent-first ordering silently never
   worked; the queue was always raw cached_at order. Now reads
   search:date:* (and q=|sort=date| legacy), page-ordered, with a
   popular-today fallback.

Verified: py_compile + pyflakes clean; _coerce_int smoke-tested on
int/str/list/dict/nested/None plus two full meta_from_cache payloads
matching both crash signatures (list, dict).
