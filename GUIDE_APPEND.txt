## v12.40h — Bot2Fetcher PDF-first pipeline (2026-08-23)

### Change requested
Cover MUST NOT be posted until the PDF is confirmed to be in hand.
Rationale: with old ordering (cover -> DM link -> wait), if @Gallery_DLBot
errored or timed out the cover sat orphaned in the DB channel. That
raced Bot 0's own COMPLETED-check: Bot 0 could see the channel has a
cover-labelled msg for that gid and think it's a done pair.

### New per-job order
    1. claim gid in Mongo
    2. meta from Turso (cache-only)
    3. DM link to @Gallery_DLBot
    4. wait for PDF document
         hard error / timeout -> `galleries.drop_claim(gid)` (delete
           the Mongo doc; gallery becomes fresh again, nothing hits
           the DB channel), move to next job
         PDF received -> continue
    5. download + normalise cover bytes
    6. inside channel-write lock, back-to-back:
         cover photo (spoiler)  -> cover_msg_id
         PDF forward / re-upload -> pdf_msg_id
    7. mark_completed with both ids + open_link

If cover post succeeds but PDF forward fails, the just-posted cover is
deleted so the channel stays clean.

### mongo_state.py new API
    drop_claim(gid)  — hard-delete the PROCESSING doc, but only if it
                       has source=='bot2fetcher'. Never touches another
                       worker's row.
    release_claim(gid) — alias, kept for back-compat.

### Stats
Added `dropped` counter (Bot 2 error / timeout / no meta), separate from
`failed` (channel-write failure after PDF was received). `/status` and
the dashboard both show it.

    🧹 dropped claim for <gid> (no cover posted)
