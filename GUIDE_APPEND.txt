## v12.42 — Bot2Fetcher: stop re-sending permanent "no images" galleries to @Gallery_DLBot

Ship date: 2026-08-25
Files: app/fetcher.py, app/mongo_state.py

Symptom (reported by Ryan): the userbot DMs https://nhentai.net/g/<id>/ to
@Gallery_DLBot; the bot replies "An error occurred: No images found after
download or ZIP extraction." — a PERMANENT failure for that gallery. But
_do_job's hard-error branch called drop_claim(), which DELETES the galleries
doc, so the next producer scan re-discovered the gid and re-sent it forever.

Fix (exactly the rule Ryan asked: error more than 2 times on the same item
→ never send again):

1) fetcher.py
   * New _NO_IMAGES_PATTERN = /no images found/i — only this error class
     counts toward the skip threshold. Other hard errors keep the old
     drop_claim + retry-next-cycle behavior (correct for transient errors).
   * The isinstance(pdf_msg, str) branch in _do_job now calls
     galleries.note_bot2_no_images(gid, text) for this class:
       - verdict "retry" (attempts 1-2): claim released, dashboard event
         "dropped", stats.dropped +1 — same telemetry shape as before.
       - verdict "skip" (attempt 3): stats.failed +1, event "failed",
         gallery never re-sent.

2) mongo_state.py — new Galleries.note_bot2_no_images(gid, error, max_retries=3):
   * $inc bot2_no_images_count on the galleries doc (upsert, ReturnDocument
     .AFTER). Persistent — survives claim release, restarts, redeploys.
   * Attempts 1-2 ("retry"): sets claim_expires=0 instead of deleting the
     row, so claim()'s existing stale-claim recovery path re-claims the gid
     on the next scan cycle. Counter is preserved.
   * Attempt >= 3 ("skip"): mark_failed(status=FAILED_BOT2_ERROR). claim()
     already returns "failed" for any FAILED_* status, so the gid is
     permanently skipped by every future scan.
   * Old rows (no counter) get up to 3 fresh attempts, then skip — no
     migration needed.
   * On any Mongo error the method fails open to the pre-v12.42 drop_claim
     path, so a Mongo hiccup never wedges a slot.

Admin surface: the gid appears in the existing Force Re-scrape admin list
(FAILED_BOT2_ERROR is in rescrape.py's _FAILED_STATUSES), so Ryan can
inspect/reset it with the existing tooling — force_rescrape() wipes the doc
and the counter with it.

Rollback: git checkout HEAD -- Bot2Fetcher/app/fetcher.py Bot2Fetcher/app/mongo_state.py
The bot2_no_images_count field on galleries docs is harmless to leave behind.
