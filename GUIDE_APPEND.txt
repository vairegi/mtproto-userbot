## v12.43 — Bot2Fetcher: construct + download cover when payload has no URL

Ship date: 2026-08-25
Files: app/meta.py, app/fetcher.py, app/mongo_state.py
(contains v12.42 + v12.43 — self-contained, no other zip needed)

Symptom (from Render log): EVERY claimed gallery was dropped:
    meta: 🔍 gallery:672776 — no cover URL in payload; keys:
          ['id', 'media_id', 'title', 'cover', 'thumbnail', ...]
    fetcher: ⚠️ 672776 — no cached meta, dropping claim
The Turso payloads DO carry cover/thumbnail keys, but legacy rows store
them as CDN-relative paths or v1-style dicts ({"t": "j"}), not URL strings.
meta_from_cache() returned None → claim dropped → gallery never delivered.

Fix (Ryan's instruction: "if it does not find it, download itself like it
used to do"):

1) meta.py — new _construct_cover_url(). When extraction from `cover`
   fails, build the nhentai CDN URL from the payload:
     Pass 1: thumbnail/cover string or dict-with-path/url (either field;
             empty dicts fall through — fixed a shadowing bug caught by
             the smoke test).
     Pass 2: v1-style {"t": "j"} dict + media_id → cover.<ext>.
     Pass 3: bare media_id → canonical cover.jpg guess.
   Only a payload with no media_id at all still returns None (truly
   undeliverable — same as before).

2) fetcher.py — _fetch_cover_bytes() now retries the other nhentai cover
   extensions (.jpg/.png/.webp/.gif) on the same base path when the
   constructed URL's extension is a guess that 404s. Successful fallback
   is logged: "cover OK via extension fallback".

3) No behavior change for healthy payloads — an existing URL string in
   `cover` passes through byte-identical (smoke test 6).

Verified: py_compile + pyflakes clean; 6 payload shapes smoke-tested
(thumbnail string, v2 dict path, v1 dict + media_id, media_id-only,
no-media_id drop, URL passthrough).

Note: this zip ALSO includes v12.42 (the no-images-after-3-attempts skip)
in fetcher.py + mongo_state.py — if you already deployed v12.42, these
files are a superset; if not, this zip alone covers both.
