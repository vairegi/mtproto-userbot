WHAT CHANGED & WHY
------------------
Three log-channel bugs, all root-caused against LIVE Mongo/Turso data:

1) Bot 2 dashboard "Turso cache: 16,527 vs In DB channel: 19,496" looked
   like deleted rows. It was a LABEL bug: cache_total is the POST-FILTER
   work queue (known-done/failed already removed by _build_queue_order),
   while "In DB channel" is the cumulative lifetime COMPLETED+PARTIAL
   count from Mongo. Nothing was wrongly deleted. Now shows:
     "Lifetime cached (Turso)"   — ALL gallery:* rows (pre-filter)
     "Cache queue (not yet done/failed)" — the work queue
     "Remaining"                 — = queue size (old formula subtracted
                                   completed_db AGAIN — double-count fix)

2) ScraperBot "finds no new items": scraping WAS working (live Mongo:
   715 new/24h) — but only details_sweeper/user-hints incremented the
   counters. list_sweeper (4 sorts x 20 pages + 66 tags x 5 pages) never
   recorded discoveries, so all that scanning was invisible. Now, after
   each page write, list_sweeper batch-checks which gids have NO
   gallery:<id> row yet (one PK-indexed IN query per page, ~25 row-reads)
   and records true discoveries via the new batched
   channel_dashboard.record_new_galleries_on_page (ONE Mongo read+write
   per page — feeds per_page_new, per_sort, new_galleries, ring_24h,
   ring_hb, ring24h_by_key, and the gid dedupe set).

3) Digest "No new galleries were scraped today": per_page_new held only
   10 user-hint entries (confirmed live) AND build_report hardcoded a
   trailing-24h window. Now the window anchors to the PREVIOUS send
   (discovery_digest_last_sent): a 10:00 digest covers everything since
   the prior send; header reads "(since 03 Sep 10:00 IST)". Cadence stays
   once-daily at BOT1_DIGEST_TIME_IST (your choice).
