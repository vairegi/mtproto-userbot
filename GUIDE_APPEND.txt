## v12.40i — Bot2Fetcher detailed log-channel dashboard (2026-08-23)

### What changed
Dashboard rewritten. Instead of one small message it now maintains
UP TO 3 edited-in-place messages in the log channel:

  MSG 1 — GLOBAL card
    • current phase (reading recent pages / listing cache / fetching /
      queue drained)
    • Turso cache total, # already in DB channel (from Mongo
      count_by_status), remaining count, ASCII progress bar
    • lifetime counters: cycles / claimed / done / failed / dropped /
      skipped-done / skipped-failed / busy
    • uptime + UTC clock

  MSG 2 — SLOT 1 card
    • account username, state emoji (😴 idle / ⚙️ working / ⏳ waiting_pdf /
      📤 posting / ⏸ resting)
    • current gid + title + pages + step
    • per-slot counters (completed/failed/dropped/FloodWaits)
    • last 3 finished jobs with ✅/❌/🧹

  MSG 3 — SLOT 2 card (only when STRING_SESSION_2 exists)

Message ids persist in Turso bot2_fetch_state['_dashboard'] so restarts
keep editing the same messages. Edits every 30 s.

### Fetcher wiring
Every state transition in the slot loop calls dashboard.slot_state() /
slot_event() — all no-ops when LOG_CHANNEL_ID is unset, so the pipeline
hot path is unchanged.

### Duplicate-work guarantee (unchanged, now documented in fetcher header)
Mongo claim insert_one(_id=gid) is atomic — exactly one of {Bot 0,
slot 1, slot 2} can win a gid. Each slot DMs @Gallery_DLBot from its own
account and polls its own inbox, so PDFs can't cross-match. Channel
writes serialise through one global asyncio lock.

### Failure visibility
If LOG_CHANNEL_ID can't be resolved (userbot not a member / wrong id),
the dashboard logs an ERROR at startup explaining exactly that, instead
of failing silently.

### Rollout
Copy `Bot2Fetcher/` over, push, Manual Deploy. Env: set LOG_CHANNEL_ID
and add the userbot account(s) to the log channel with post rights.
