GUIDE_APPEND — ScraperBot v1.24  English-Only Enforcement
Ships in one drag-and-drop zip (BOT 1 files only — BOT 0 / BOT 2 untouched).
Base commit: 8d60a95 (2026-08-30, v12.47-era repo).
================================================================================

WHY
---
BOT 1 was caching non-English galleries into the shared Turso cache, and
BOT 2 was then downloading PDFs for them. Root cause: only ONE of BOT 1's
three fetch paths was language-filtered.

  * Chip pages (empty query)  → already sent query=language:english.
  * Tag pages (trending tags + EXTRA_TAG_SORTS) → sent `tag:<slug>`
    VERBATIM with no language filter.  ← main leak
  * Trending-tags discovery → hit /api/v2/galleries?sort=popular-today
    with no filtering, so non-English galleries steered the tag ranking,
    which then seeded non-English tag sweeps.

Cache-key parity is SAFE: the Turso key is computed from the user's raw
query inside list_sweeper (search:q=<tag>|sort=<s>|page=<N>), NOT from the
upstream request, so BOT 0's typed-search lookups still hit the same keys.


WHAT'S IN THIS ZIP
------------------
  ScraperBot/app/hf_scraper_lite.py            (query guard)
  ScraperBot/app/services/trending_tags.py     (client-side language filter)
  ScraperBot/app/config.py                     (new ENGLISH_ONLY knob)
  ScraperBot/tests/test_english_only.py        (NEW — unit tests)
  GUIDE_APPEND.txt                             (this file)


DETAIL
------
1. hf_scraper_lite.fetch_search_page()
   Non-empty queries now get ` language:english` appended when
   settings.english_only is on, unless the query already carries an
   explicit `language:` filter. nhentai supports compound queries
   (e.g. "tag:incest language:english") so this is server-side filtering.

2. trending_tags.refresh_if_needed()
   /galleries cannot take a `query` param, so filtering is client-side:
   each sampled detail's tags are checked for a `language` tag; galleries
   whose language is not english (or missing — treated as acceptable) are
   excluded from the frequency tally.

3. config.py
   New knob `english_only` (env ENGLISH_ONLY, default true). Set
   ENGLISH_ONLY=0 on Render to revert to all-languages behavior without
   a redeploy. Both modules getattr-guard the setting so a stale config
   can never crash them.

No contract changes. No vendored turso_cache changes. No BOT 0 / BOT 2
changes. Mongo/Turso schemas untouched.


DEPLOY
------
Drag the zip onto the repo, redeploy ONLY the ScraperBot (BOT 1) service.
No env changes required — ENGLISH_ONLY defaults to true.

POST-DEPLOY VERIFICATION SIGNS (BOT 1 logs)
-------------------------------------------
  * Tag sweeps now show compound queries upstream; cached rows contain
    only English-tagged galleries.
  * Next trending_tags refresh (every 24h) logs the same tag set shape
    but harvested from English-only samples.
  * details_sweeper keeps warming whatever ids list pages hand it; those
    ids now come from English-filtered list pages only.

EXISTING NON-ENGLISH CACHE ROWS
-------------------------------
Rows already in Turso/Mongo are untouched by this patch — they simply
stop being refreshed. Cleanup options (purge non-English gallery:* rows
from Turso, purge from relaybot.galleries + BackupDB channel posts) are
a separate follow-up we'll plan next — needs your decision on whether to
also delete already-posted Telegram channel messages.
