## v12.41 — BOT 0: cron supervisor + cache Mongo-read gate + force-join cache

Ship date: 2026-08-25
Files: worker.py, miniapp/backend/app/services/cron_orchestrator.py,
       miniapp/backend/app/services/nhentai_cache.py,
       miniapp/backend/app/services/force_join.py

1) Cron consolidation (#1). NEW cron_orchestrator.py supervises the three
   background crons (prefetch_cron, dedup_cron, details_prefetch_cron) as
   child tasks under ONE supervisor. worker.py now spawns one
   `cron_orchestrator` task instead of three separate ones. Each cron keeps
   its own run_forever() / cadence / env toggles UNCHANGED — this is
   supervision, not a rewrite. A child crash is now loud-logged and respawned
   after a 30s backoff instead of dying silently. rescrape.py is a library
   (no run_forever) so it is not supervised.

2) nhentai_cache.py (#2). get() already short-circuited on a Turso hit. The
   change gates the Mongo read that ran on a Turso MISS: new env
   BOT0_CACHE_MONGO_READ_FALLBACK (default "0" = skip Mongo). With both Mongo
   mirrors off (BOT0_NH_MONGO_WRITES=0 here, BOT1_CACHE_MONGO_MIRROR=0 on
   ScraperBot) a Turso miss can never be rescued by Mongo, so the fallback was
   a wasted round-trip on every cold miss. Set the env to 1 to restore legacy.

3) force_join.py (#3). Mongo-only membership cache. getChatMember verdicts are
   cached per (user_id, chat_id) in `miniapp_force_join_cache` with a TTL
   (FORCE_JOIN_CACHE_TTL_SEC, default 300s). Repeat deliveries in the window
   are one Mongo read instead of N Bot API calls. Negative results cached too.
   The admin-bot 'I've joined' (fj:check) path bypasses the cache by calling
   _is_member_live directly, so a just-joined user is never stuck behind a
   stale False. Added invalidate_user(user_id) hook (not wired to UI yet).
