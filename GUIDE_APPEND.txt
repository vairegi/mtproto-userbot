## v12.40d — Bot2Fetcher cache-only meta + emoji logging (2026-08-23)

### Symptom (v12.40c log)
Bot worked (scan 7411 galleries, claiming jobs) but every job failed:
    GET https://nhentai.net/api/gallery/619612 "HTTP/1.1 403 Forbidden"
    upstream meta 619612 -> HTTP 403

### Root cause
`meta_from_cache` was rejecting good Turso payloads (shape check too
strict — `p.get("id")` failed on some rows) so the bot fell through to
the live nhentai API on every job. Render's IP is 403'd by nhentai, so
every job died at the meta step.

### Fix
1. **Cache-only mode.** nhentai upstream fallback REMOVED entirely.
   Render can't reach nhentai reliably, and Bot 1's Turso cache is the
   authoritative source. Missing cache row → FAILED_SCRAPE, move on.
2. **Looser meta check.** Accepts cover, cover_url, or thumb_url. Logs
   the exact reason a row is rejected (no row / not dict / no id / no
   cover) with the payload keys so the next miss is diagnosable from the
   log alone.
3. **Full emoji logging.** Every pipeline step now logs with an emoji:
   🚀 boot, 🤖 slot auth, 📺 channel resolve, 📚 gallery list, 🔥 recent
   seed, 📡 scan cycle, 🧵 worker start, 🎯 claim, 🔍 meta lookup,
   📄 page count, 🖼 cover post, 📨 DM sent, 📥 PDF received, 📤 PDF
   posted, ✅ done, ❌ failed, ⏭ already done, 🔒 busy, ⏰ timeout,
   🚧 FloodWait, ⏸ rest, 💤 queue drained, 🚨 Turso error.
   `grep "✅"` shows completions; `grep "❌"` shows failures.
