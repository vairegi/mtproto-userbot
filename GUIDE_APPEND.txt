GUIDE_APPEND — v12.62 (2026-09-05) — broadcast buttons + /similar speed + loader
================================================================================

1) BROADCAST BUTTONS FIX (admin_bot.py)
   Root cause: Telegram Bot API copyMessage copies media + caption +
   caption_entities (hashtags, spoiler styling, links) verbatim — but NOT
   reply_markup. Your broadcasts with tag/link buttons were arriving as
   plain image+caption because the keyboard was never passed. Fix: the
   source message's reply_markup is now forwarded on every copyMessage
   call. Caption tags (#hashtags in the caption text) were already
   preserved — only buttons were being dropped.
   Test: reply to a post that has buttons with /broadcast — recipients
   receive the buttons too.

2) /SIMILAR SPEED FIX (miniapp/backend/app/services/similar_mongo.py)
   Root cause of the 10-15s: every detail-sheet open ran a full-corpus
   Mongo scan (15,792 docs, JSON-parsed and scored in Python). Fix:
   per-gallery result cache in Mongo-2 (key similar:<gid>, TTL 30 min via
   SIMILAR_CACHE_TTL_SEC). First open of a cold gallery still scans;
   every repeat open within 30 min answers in ~50ms.
   Render log: "source=MONGO2-CACHE age=Ns -> 8 cards" on cache hits.
   Rollback: SIMILAR_CACHE_TTL_SEC=0 disables the cache (miniapp service
   env). Freshness note: new uploads only appear in a gallery's Similar
   row after that gallery's cache entry ages out (<=30 min).

3) LOADING EFFECT (miniapp/frontend/js/plugins/detail-sheet.js)
   The Similar section now mounts VISIBLE with 6 shimmering skeleton
   cards (same shimmer idiom as the mini-app's other loaders) the moment
   the sheet opens; real cards replace skeletons when the fetch lands.
   If a gallery has zero similar results the section hides itself.
   Importmap rule honoured: all 5 detail-sheet import sites bumped
   ?v=12.57 -> ?v=12.62 (bookmarks.js, profile.js, search.js,
   home-rows.js, core/app.js) so Telegram WebView cannot serve the old
   cached module.
