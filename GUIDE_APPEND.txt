WHAT CHANGED

1. miniapp/backend/app/services/scraper_bridge.py — THE GRAY BUTTON FIX.
   Root cause found in your Render log: page-2 requests returned
   "TURSO CACHE HIT page1 + page2" and STOPPED. The aggregation loop's
   condition `while len(collected) < want_total` exits as soon as the
   requested window is fillable — page 2 needs upstream pages 1+2, i.e.
   exactly 50 cards, i.e. exactly start_offset+per_page — so the old
   cushion check `len(collected) > start_offset+per_page` could never be
   true and has_more was always False. v1.22.5's stale-read fix was
   necessary but not sufficient.
   Fix: after slicing the window, probe the NEXT chip cache key
   (search:<sort>:page<upstream_page>) directly in Turso. One GET; stale
   rows count when USE_OLD_CACHE=1. If the row exists and is non-empty,
   has_more=True and the › button stays lit for every warmed page.
   Only applies to chip/empty-query browses (the Discover sort tabs);
   typed searches keep their old behavior.

2. miniapp/backend/app/services/dedup_cron.py — DM SPAM FIX.
   Your DMs showed "🧹 Dedup sweep ⚠ mongo sweep raised: ...27017: timed
   out" every 12h. Atlas free-tier (M0) idle-closes connections; one
   cursor timing out is transient — the next sweep reconnects. The alert
   classifier now filters pymongo NetworkTimeout / ServerSelectionTimeout
   / "timed out" messages out of the wake-the-admin path. Real errors
   (auth failures, write errors, anything non-timeout) still alert.
