## ScraperBot v1.21 — dashboard silent-400 fix (2026-08-25)

### Symptom (Render log)
    POST api.telegram.org/bot.../sendMessage "HTTP/1.1 400 Bad Request"
every ~3s, forever. No dashboard message ever appeared in the log
channel. Sweeps themselves were fine — only the Telegram side failed.

### Root cause
channel_dashboard._tg_api swallowed Telegram's error body. On any 400
the code had `{"ok": False, "description": "..."}` in hand but never
logged it, so the actual reason was invisible. Three possible 400
sources all existed simultaneously:

  1. `chat_id` serialised as a STRING ("-1003790521529") — Telegram
     prefers an int for channel ids and intermittently 400s on strings.
  2. HTML parse error from the `<blockquote>` wrap — any unescaped `<`
     in a Mongo-sourced activity line broke the payload with
     "can't parse entities".
  3. Text over 4096 chars on phases with many extra_tag_sorts.

On top of that, the writer loop had no circuit breaker: a persistent
400 kept the loop calling Telegram every 3s and occasionally crashed
the task hard enough that Render restarted the service.

### Fix (channel_dashboard.py only, no other file touched)
- `_tg_api` logs EVERY non-ok response at WARNING with Telegram's own
  `description` field — the next failure is diagnosable from the log.
- `_coerce_chat_id()` — numeric-looking ids sent as int.
- HTML `<blockquote>` → Markdown v1 fenced code block (```\ntext\n```).
  No entity-parse surface at all. Bonus: monospace layout the dashboard
  always wanted.
- Body hard-capped at 3900 chars with a `\n…` truncation marker.
- Circuit breaker: 5 consecutive failed sends pauses the writer 300s
  with one ERROR line explaining the fix, then resumes.
- Top-level try/except already wrapped the tick; widened so an
  unexpected Telegram shape can never crash the task.
- Heartbeat and phase-edit flows both moved to the same fenced format.

### Verify after deploy
Boot + first phase should produce in Render log:
    📊 dashboard message posted (id=NNN)
and the log channel shows one monospace card:
    [3]
    ➥ Total galleries: …
    ➥ New this phase: …
    ➥ Popular Today      ▸ N new · M cached
    …
    ———
    ➥ Now: sweep popular-today p5
    ➥ Last gallery: 498489
If a 400 ever happens again, the log now shows Telegram's exact
description on the same line as the failure, e.g.:
    📊 tg sendMessage failed [400]: Bad Request: chat not found

### Rollout
Copy `ScraperBot/app/services/channel_dashboard.py` over the existing
file, commit, push, Manual Deploy on the ScraperBot Render service.
No env changes, no other files modified.
